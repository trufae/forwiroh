# Forwiroh 0.2.0

This release introduces an opaque Rust `Forwiroh` API with owned response models,
typed errors, and distinct tunnel and VPN session identifiers. New integrations
can use this facade without depending on Iroh endpoints, Tokio channels, or
internal state. Existing low-level Rust APIs remain available. Extensible Rust
enums are now non-exhaustive; existing exhaustive matches on `Command` and
`TransportMode` need a fallback arm. See the
[Rust migration guide](https://github.com/trufae/forwiroh/blob/v0.2.0/docs/rust-api.md).

The control API adds `api_info` for version and capability discovery, canonical
command names, and machine-readable error codes. Control API v1 aliases and the
C ABI v1 remain supported. Swift gains typed identifiers and response models
while retaining its existing string methods. Frozen Rust, C, C++, Swift, and
socket consumers now guard compatibility in CI. See the
[control API contract](https://github.com/trufae/forwiroh/blob/v0.2.0/docs/control-api.md).

Policy editors can read a policy revision and apply a patch that preserves
untouched fields. Stale updates fail with `policy_conflict`; owned policy models
preserve unknown fields through decoding and encoding. Legacy policy setters
retain their existing schema and replacement behavior.

Tunnel stops are idempotent and reject requests for the wrong tunnel kind.
CLI approval and stop commands accept generated IDs that begin with a hyphen.
VPN commands honor explicit TUN selection and legacy packet-session aliases.
The C packet API validates receive-buffer capacity without consuming a packet
and adds functions that return detailed packet errors.
The Android JNI bridge uses the canonical declarations and packet-buffer size.

Rust and dependencies, the Android Gradle wrapper, and the Nix pin are updated.
Apple mobile builds include a libc compatibility pin. The apps and documentation
also use the refreshed Forwiroh cable logo.
